# AI 工具

除摘要之外，AI 可用工具自主检索**日志压缩包**与**项目代码仓库**内的原始内容（只读）。

## 日志压缩包工具

由 `log_tools_enabled` 控制（默认开启，**不依赖 repo 是否启用**）。分析路径与追问路径都会开放这些工具。

| 工具 | 用途 |
| --- | --- |
| `log_list_files` | 列出日志包内某目录的文件 |
| `log_search` | 在日志包文本文件中正则搜索（**摘要不够用时找原始证据**） |
| `log_read_file` | 读取日志包内某个文本文件（支持行范围） |
| `log_list_images` | 列出日志包内全部图片（确认能附哪些图） |

> **摘要必然有取舍。** 日志包工具让 AI 能像读仓库一样直接读压缩包里的原始文件——
> 例如摘要里被截断的完整堆栈、某个配置项的原文、某行日志的上下文。
> 追问时也会开放这些工具，因此 AI 不再只能回答「摘要中未包含」。
> 日志路径会随 UI 不同而变化（MXU 根目录 `maafw.log`、MFAAvalonia `debug/maafw.log`、
> MaaFwApp `log/maafw.log` 与 `pi/debug/maafw.log`），工具按压缩包内实际路径访问。

### 解压到目录后读文件（对齐 dsh）

工具**不再在内存里解压 ZIP 成员**，而是先把压缩包安全解压到目录，再按普通文件读写
（与 dsh 的 `read` 工具一致：模型侧工具面向真实文件系统）：

- **按需解压**：`log_tools_enabled` 只是开放工具，模型第一次调用时才真正解压；
  一次分析/追问内多次调用复用同一目录。
- **解压位置随历史开关决定**（详见[日志归档](history.md)）：

  | 情形 | 解压目录 | 生命周期 |
  | --- | --- | --- |
  | `history_enabled` 开启 | 分析中暂存于 `data/<配置>/history/.staging/<session>`，归档时整体移动到 `data/<配置>/history/<记录>/extracted/` | 保留到该记录被清理（即追问窗口结束/保留期到期），追问与重启后**直接复用**，不再重复解压 |
  | `history_enabled` 关闭 | 系统临时目录 `maa_logs_*` | 分析结束即删除 |

- **复用判定**：`extracted/` 下写有标记 `.maa-extracted.json`，记录压缩包 `size + mtime` 指纹
  与成员列表；指纹一致才复用，压缩包换过或目录被改过则整目录重解压，避免新旧文件混合。
- **崩溃残留**：`.staging/` 下的目录不属于任何历史记录，由历史清理周期（`history_cleanup_interval_hours`）
  统一清扫；重启后残留不会累积。
- **落盘前校验**：成员名拒绝绝对路径 / 盘符 / `..`；拒绝符号链接条目与凭据类文件；
  实际落盘路径再次确认在解压根目录内。
- **大小只有一道闸门**：下载完成后 `probe_archive()` 只读 zip 中央目录求和，
  超过 `max_total_uncompressed_mb`（默认 **1024 MB**）直接判定“内容过多”并跳过整次分析
  （不提取摘要、不准备仓库、不调用 AI）。因此进入后续流程的包一律视为“已符合限制”，
  解压与读取都不再逐文件比对大小；解压时仅按**实际写出字节**复核总量，
  防止 zip 头声明造假（超限即中止并清理，不会退化为部分内容）。
- 解压失败的成员被跳过并记入备注（`log_read_file` 会直接说明“不可用”的原因），
  不会让整次分析失败；成员数上限 3000。

## 项目代码仓库工具

仅在 `repo.mode = "agent"` 时提供给 AI，见 [项目代码参考](repo.md)。

| 工具 | 用途 |
| --- | --- |
| `list_dir` | 列目录，了解仓库结构 |
| `search_repo` | 正则搜索，定位节点定义 / 字段 / 阈值（最高效） |
| `read_file` | 读文件，支持 `start_line` / `end_line` 分段读大文件 |
| `list_tags` | 列出可用版本 tag |
| `pull_latest` | 从当前配置的远端更新默认分支；不接受 URL 或 Git 命令 |
| `checkout_ref` | 获取 tag / commit；仅在 `allow_ai_switch_tag` 开启时提供（受 `max_tag_switch_rounds` 限制） |

## 沙箱安全

- 工具路径仅接受相对路径，拒绝 POSIX / Windows 绝对路径、盘符路径、任何 `..` 上跳组件与空字节
- 仓库工具、附件和代码参考共用实际路径校验：先拒绝任何 `..`，再解析符号链接并判断是否位于仓库根目录内。搜索和目录列表逐条校验
- 日志包参数与 ZIP 成员名使用相同的相对路径校验，含 `..` 的成员一律拒绝；附件、摘要和工具共用校验，非法成员不会进入列表、搜索、档案布局识别或版本提取
- 仓库路径不存在时返回相对路径提示；路径解析异常不向工具结果写入主机绝对路径
- 拒绝读取 `.git` 内部、二进制文件与[凭据密钥类文件](attachments.md#敏感文件保护)
- 目录列表与日志包图片列表也隐藏凭据密钥类条目；符号链接的请求路径与解析后路径都要通过敏感路径检查
- 校验后使用解析得到的路径；当前不提供目录被并发替换时的原子打开保证
- 单次读取受三层上限约束（结构对齐 dsh 的 `read` 工具）：
  - **行数/窗口**：`start_line` / `end_line` 指定 1-based 行区间，超范围会明确报错而不是静默夹到末行
  - **单行宽度**：超长行截断到 2000 字符并标注“行已截断到 2000 字符”，一行超长 JSON 不会吃掉整段结果预算
  - **字节/字符**：日志包 `read_file` 先流式跳到 `start_line`，再对**本次返回窗口**按
    `max_log_file_read_kb`（默认 512 KB）与 `max_tool_result_chars` / token 预算计数；
    读满后可用 `start_line` 继续，深处的行不会再因为“只读文件开头”而不可达。
    `log_search` 按 64 KB 分块 + 8 KB 行缓冲**流式扫描完整文件**，不受单文件字节上限限制；
    匹配使用完整行（单行缓冲上限 8 KB），只有回显截到 300 字符。仓库 `read_file` 仍按 `repo.max_file_kb`
    （默认 256 KB）只读文件开头，结果再受 `max_tool_result_chars` / token 预算裁剪
  - 三种截断各有明确续读提示：`受结果长度限制，可用 start_line=N 继续读` /
    `本次已读取满 N KB，可用 start_line=N 继续读` / `已到 end_line，可用 start_line=N 继续读`
  - 空文件 / 空成员返回明确的“无文本内容”，不会伪造空结果
- 读取仓库文件；Git 更新/切换仅通过固定工具执行，**绝不执行仓库中的任何代码或任意 Git 命令**

## 限制

agent 模式受三重限制，避免 token 与耗时失控：

| 设置项 | 默认 | 说明 |
| --- | --- | --- |
| `max_tool_rounds` | `8` | 工具调用最大轮次 |
| `max_tool_calls_per_round` | `6` | 单轮最多执行的工具数 |
| `agent_deadline_seconds` | `600` | agent 循环总时长上限 |
| `max_tool_result_chars` | `30000` | 单次工具结果字符上限 |

> 仓库获取（克隆 / 更新）的时长上限见 [项目代码参考](repo.md)：分析现场只做**浅克隆**
> （`shallow_clone_timeout_seconds`），完整克隆由后台预下载负责（`preload_timeout_seconds`），
> 更新默认分支另有 `update_timeout_seconds`。

路径安全回归测试：`python -m unittest discover -s tests -v`。
